# 社区版 106 模型看板恢复说明

## 模型口径

社区版模型名单来自 `auto_board/run_community_106.yaml`，当前固定为：

- TorchBench：58 个
- HuggingFace：30 个
- TIMM：18 个
- 合计：106 个

这份名单和内部全量流水解耦。内部网站可以继续展示所有模型，社区版网站只展示这 106 个模型。

## 从已部署网站恢复

网页部署目录中的日包可以作为已经发布的数据源。即使服务器上的 `raw_data` 丢失，也不需要重新跑模型，只需要把完整的网站目录复制到一个可信工作目录，再执行投影：

```bash
python auto_web/build_community_dashboard.py \
  --source-root /path/to/restored/website \
  --output-root /path/to/community-website \
  --model-set auto_board/run_community_106.yaml
```

脚本会：

1. 复制网页 HTML、静态资源和公共辅助文件。
2. 过滤 `board.json` 中的模型、GPU baseline 和 catalog。
3. 过滤 `dvm/` 和 `triton_experimental/` 下的每日 JSON。
4. 重建两个后端的 `manifest.json`。
5. 生成只包含 106 个模型的 `full_model.txt`。

脚本只写入新的输出目录，不修改源网站目录，也不读取 raw benchmark 日志。

这 19 个模型表示 training 对比数据尚未覆盖它们，不等于 106 模型名单发生变化。

inference 对比文件 `benchmark_Comparison Table_35042129962_to_35549578193.csv` 包含 831 条配置记录，对应 **106/106 个唯一模型**：

- TorchBench：58/58
- HuggingFace：30/30
- TIMM：18/18

因此外部社区看板的完整性检查应以 inference 数据为准。该文件按 8 种 Inductor 配置展开，模型级别统计为：101 个模型至少有一条 `pass`，85 个模型所有现有配置均为 `pass`，其余模型包含 `fail_to_run`、`missing data`、`eager_two_runs_differ` 或 `fail_accuracy` 等状态。缺少或失败的配置不能从模型名单中删除，应在网页上保留并展示对应状态。
